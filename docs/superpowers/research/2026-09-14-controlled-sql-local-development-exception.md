# 受控 SQL 探索本地开发例外

日期：2026-09-14
状态：**仅授权本地开发；不构成发布门禁通过**

## 决定

项目所有者在语义目录与 Schema 检索 Task 1–5 已完成本地实现、独立审查、父级回归和日期化验收后，明确要求继续下一子项目。因此允许在 Task 11 统一发布门禁第 4–7 项尚未完成时，本地实施 `2026-09-14-controlled-sql-exploration.md` 的 Task 1–6。

该决定只解除受控 SQL 探索的本地实施限制，不修改总设计中的生产发布标准，也不把未执行验证记为通过。

## 允许范围

- 仅实施受控 SQL 探索计划 Task 1–6；
- `SEMANTIC_CATALOG_ENABLED=false` 与 `CONTROLLED_SQL_ENABLED=false` 均保持默认关闭；
- 只使用本机 `*_test` 数据库、stub 模型和离线测试；
- 允许按计划新增并锁定 `sqlglot` 依赖；
- 允许编写 `020_controlled_sql_exploration.sql`，并仅在本机 `*_test` 数据库顺序执行和幂等重放；
- 允许使用 `bi_app` / `bi_reader` 在本机测试库验证只读、底表拒绝、成本门禁和诊断权限；
- 每个计划 Task 继续执行原生 high 子代理、独立审查、父级验证和单独提交；
- 两个 feature gate 关闭时，现有 Tool、数据库读取和用户可见行为必须保持不变。

## 仍然禁止

- 在生产或预发布流量中启用语义目录或受控 SQL；
- 真实 provider smoke、26 题 live 验收或真实模型探索；
- 生产/预发布数据库访问、迁移、来源同步、回填、对账、部署、OIDC、SSE、计划任务、备份或恢复操作；
- 真实上架价、库存或其他来源就绪声明；
- PDD 连接器、来源、支付能力、凭据或 onboarding；
- 把受控聚合探索描述为“任意 SQL”或“通用 Text2SQL”；
- 在本例外下开始 approved 查询学习记忆、隔离分析 Agent 或持续库存通知。
