## 5. 推荐实施顺序

### P0：真实名称和全量范围验收

- 先把“全量”固定为「已授权店铺 × 业务实体 × 历史窗口 × 获准字段」，默认先收口抖音已有口径。全平台支付汇总需要各平台独立来源和对账证据。
- 接入订单行名称快照、商品 / SKU 主档、店铺展示名，区分成交时名称与当前名称；同名、多 SKU、改名、下架均能定位。
- 模型继续使用稳定 opaque ref；授权用户在应用侧解析真实名称。店铺 / 商品业务名称可以展示，真实 ERP 主键无需进入聊天或提示词。以后需要把真实名称送给模型时，应单独定义新的投影契约。
- 同步历史、增量、对账覆盖交付清单；近期缺口显式展示，绝不自动缩短“最近七天”后冒充完整回答。
- 商品退款、库存、成本、采购分批接入，各自补事实表、覆盖和指标验收；不要求把 API 的每个字段全塞进库。

**验收问题：**「最近七天哪个商品卖得最好？」展示实际名称、SKU / 父项口径、期间和截止；数据缺失时展示具体缺口。「这款商品」追问能稳定定位，不能因名次变化或超过 26 件而指错商品。

### P1：查询闭环可靠性与机器状态

- 统一 typed recovery：参数缺失→澄清；参数非法→最多一次修正；无权限→停止；缺覆盖→说明缺口并给可选窗口；临时连接失败→预算内有限重试；超时→终止并建议缩小；Artifact 保存失败→禁止发布成功。
- 区分原请求、建议范围和实际执行范围。相同规范化请求在同轮、同一数据版本下复用成功结果，避免重复调用耗尽预算。
- 增加无需模型的确定性摘要兜底。记录 root request、attempt、recovery count、termination reason 和数据血缘。
- 补齐模板版本、指标定义版本、Schema 版本、catalog 版本、数据批次 / 截止信息。多次查询用于同一分析时明确一致性策略。仅有 data_as_of 和 hash 无法实现历史数据重放；要重放需保留版本化数据，或明确只复现已冻结 Artifact。

**验收：** 同一缺覆盖请求不反复查询、不偷改时间范围；工具预算或模型服务耗尽时仍展示可信结果 / 明确缺口；不会把过时运行 revision 当数据快照。

### P2：Schema / 业务语义检索

- 建立 catalog：实体、视图、列、中文业务词、指标定义、粒度、时间归属、币种、JOIN 关系与基数、来源 / 覆盖、访问范围。
- 首版使用声明式目录和关键词 / 别名检索。先测召回缺口，再决定是否引入向量检索。
- 分为 retrieve candidates → select schema → validate join/grain 三步。支付事实和退款事实独立聚合后再 JOIN，避免重复放大金额。

**验收：** 固定题库中所需视图 / 列召回覆盖达到预设门槛；不能跨授权范围召回；含歧义的问题返回澄清；记录候选与最终选择便于复盘。

### P3：受控 SQL 探索子图

- 固定经营指标继续使用现有模板，新增探索型 Tool 处理现有指标不能表达且已具备数据的分析。
- 路径：解析意图 → 授权 → 检索 / 选择 Schema → 生成候选 SQL → AST / 权限 / 粒度校验 → EXPLAIN 预算 → 只读执行 → 错误分类 → 有限修复 → 保存 Artifact。
- 独立只读数据库身份；参数化值；单语句；允许的 reporting 视图和函数；行数、时间、扫描预算。SELECT 形式本身不能保证安全，须拒绝副作用函数和写入 CTE。
- EXPLAIN 估算只作预检，运行时限额仍生效。权限错误不得通过换表绕过，SQL 修复不得修改原始业务问题。

**验收：** 越权、写入 CTE、危险函数、多语句、错误 JOIN、超量结果被阻止；成功 SQL 与固定模板在共同题目上数值一致；有限次数失败后正确终止。

### P4：评测与学习型记忆

- 评测从 P0 起贯穿所有阶段；学习写回在查询路径稳定后开启。
- 仅保存获准的问题表示、规范化查询、检索 / SQL 计划、口径版本和结果引用，不把完整聊天、明细或过期金额作为长期 few-shot。
- “高置信”由可检验条件定义：权限 / SQL / 口径校验通过、覆盖完整、结果交叉验证、版本适配、无未解决歧义；不能使用模型自报置信分。自动提升初期关闭，先走人工批准。
- few-shot 检索必须过滤 approved、租户 / 权限和版本。Schema / 口径变化触发失效；用户否定的结果进入 rejected。

**验收：** 错误示例、覆盖不全结果、未批准候选均无法被检索进 few-shot；每条提升可解释、可撤销。

### P5：隔离分析子 Agent

- 主 Agent 提交分析目标、已授权数据集引用、数据版本、预算；子 Agent 自有消息和机器状态。
- Python / 统计代码在独立受限进程或容器执行，配置 CPU、内存、超时、文件限额；不携带业务库或模型之外的长期密钥，默认不联网。
- 返回简短结论、局限、引用及图表 / 表格 Artifact；代码 stdout、临时表和详细执行记录保留在子任务空间，不拼回主 Agent 历史。
- 先做描述、比较和分解；没有实验或额外证据的下降原因只能作为假设。

**验收：** 取消、超时、异常不拖死主对话；多数据集版本不一致时拒绝混算或显式标注；主上下文只增长有限摘要和 Artifact 引用。
